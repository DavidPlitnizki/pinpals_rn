## 🎯 Продуктовая идея

**Pinpals — это не поиск мест, это разметка того, чего ни на одной карте нет.**

Ключевой вывод (2026-08-07): поиск мест — commodity. Mapbox/Apple Maps/Google Maps
всегда будут искать лучше нас, конкурировать в поиске — проигрышная битва по
определению. Настоящая ценность — **личные/групповые места, которых нет ни в одной
картографической базе**: место встречи, секретный спот, памятное место — и заметка/фото
к нему. Это то, что Google Maps никогда не построит, потому что это не бизнес-объект и
не масштабируется для них так, как для нишевого приложения.

Отличие от Apple Maps в одной фразе:
- Apple Maps отвечает на вопрос **«куда мне ехать?»**
- Pinpals отвечает на вопрос **«что значат для меня эти места?»**

Роли двух систем поиска в приложении:
- **Внешний поиск (Mapbox Search Box API)** — второстепенная утилита: найти реальный
  бизнес (кафе, магазин), навигация, контекст «что рядом». Не источник дифференциации.
- **Свои места (`Place` + `PlaceNote`)** — ядро продукта. Здесь работают фильтры,
  категории, теги — то, чего нет ни у одной карты.

Кита дифференциации:
1. **Memory/Annotation Layer** — места как личный/групповой контекст (фото, заметка,
   настроение), а не адреса
2. **Meeting Negotiation** — координация встреч внутри приложения, с шарингом ссылкой
3. **AI-ассистент** — разговор с личным атласом (Phase 1C, см. ниже) — строится только
   после подтверждённого роста, не раньше
4. **Taste Graph** — персональный граф предпочтений на основе пинов (Phase 2+)

## 🧪 Стратегия валидации — обязательна к прочтению перед тем, как строить что-то новое

**Сначала бесплатный минимальный тест, потом фичи.** Порядок такой:

1. Собрать TestFlight-билд из уже готового Phase 1 (см. чеклист ниже — минимум блокеров)
2. Отдать 15-30 реальным людям из целевой ниши (не случайным из App Store)
3. Мерить **не retention сам по себе**, а **share/invite rate** — приглашает ли
   пользователь хотя бы одного человека / делится ли хотя бы одним местом с кем-то.
   Это единственный сигнал, который имеет значение: если люди отмечают места только
   для себя и никому не показывают — сеть не построится, и премиум-фичи это не спасут
4. **Только если** share/invite rate реальный — переходим к Phase 2 (друзья, шаринг
   локации) и Phase 1C (AI-ассистент как платная фича)
5. **Если сигнала нет** — не тянем фичи дальше, меняем нишу/аудиторию, а не пытаемся
   докрутить продукт новыми фичами. Соцфичи усиливают уже липкий продукт, а не создают
   липкость с нуля

**Явно НЕ делаем до подтверждённого роста** (сознательно отложено, чтобы не терять время
на то, что может быть выброшено):
- Calendar-интеграция (`expo-calendar`) — полирует то, что происходит уже после
  создания встречи, не влияет на share rate, добавляет лишний permission-запрос у Apple
- AI-ассистент Ask — дорогая фича без смысла тестировать вслепую
- Реклама как модель монетизации — конфликтует с личным/эмоциональным позиционированием,
  и на маленьком DAU не даёт значимого дохода. Монетизация — feature-gated подписка,
  не ads
- Полная нативная интеграция с Apple Maps поиском (MKLocalSearch через кастомный
  native-модуль) — не нужна, у Mapbox Search Box уже есть то же самое через HTTP,
  дублировать нативным Swift-кодом бессмысленно

## 🗂 Модели данных (`src/models/types.ts`, Zustand-сторы в `src/store/`)

> Стек — TypeScript/React Native, не Swift/SwiftData. Все модели живут в

> `useMeetingsStore`, `useSavedRoutesStore`, `useSearchFiltersStore`).

### Place — категория vs теги (важное архитектурное решение, 2026-08-07)

Категория — **маленький фиксированный enum**, не пользовательский ввод:
- Держит систему иконок/цветов пина на карте (`CATEGORY_COLORS` в `src/shared/constants.ts`)
- Работает как основной быстрый фильтр (чипы в `useSearchSheet.ts`)
- Полностью открытые пользовательские категории **сознательно отклонены** — ломают
  фильтрацию (дублирующиеся названия одного смысла: "off-road" vs "dirt track"),
  ломают систему иконок пина, ухудшают холодный старт (пустой список вместо готовых чипов)

Теги — **свободный пользовательский ввод поверх категории** (`Place.tags: string[]`,
уже частично реализовано через `TagInput`):
- Вся гибкость без слома фильтров: "тихое", "утром", "с Машей", "surface: dirt",
  "есть парковка"
- Не участвует в системе иконок — чисто текстовый фильтр/поиск

```ts
// Place — расширения поверх уже существующих полей
tags: string[]           // свободные пользовательские теги
visitCount: number        // сколько раз был
lastVisited?: string      // ISO-дата последнего визита
isFavorite: boolean        // уже есть
```

```ts
// PlaceNote — заметка/воспоминание к месту, уже есть mood/companions/colorTag
mood?: MemoryMood
companions: string[]      // Phase 1: строки, Phase 2: связь с реальными UserProfile
colorTag?: string
photoUris: string[]
```

```ts
// Meeting — статусы и кандидаты на голосование
status: MeetingStatus            // draft | proposed | confirmed | done — уже есть
proposedPlaceIds: string[]       // поле есть в сторе, но не заполняется/не используется в UI
participants: string[]
```

## 📱 Экраны — что менять

### 1. Map (Карта)

**Карта остаётся на Mapbox (2026-08-07, решение отменено после проверки).**
Изначально планировали сменить рендер на `react-native-maps`/Apple Maps, мотивация была
"раз покупаем Apple Developer — заодно получим поиск получше". Проверили фактическим
запросом и типами community SDK: у Apple Maps Server API `/search` **нет** телефона,
сайта, часов работы и фото — Mapbox Search Box уже отдаёт больше (телефон, сайт, часы —
не хватает только фото, которых у Apple тоже нет). Раз поиск и Directions/навигация
всё равно остаются на Mapbox, менять только рендер карты означало бы держать два SDK
карт одновременно ради чисто косметической выгоды — не стоит того объёма работы
(переписать `MapView`/`Camera`/все маркеры/`RouteLineLayer`) перед TestFlight-тестом.
**Решение: не трогать карту до подтверждённого роста**, см. стратегию валидации.

**Стать**: Живая карта того, чего нет ни на одной другой карте.

Изменения:
- **Пины окрашены по настроению** (mood color из воспоминания), а не только по категории
- **Фильтры**: по категории (быстрые чипы) / по тегу / по периоду / по людям
- **"Год назад"** — кнопка-тригер, подсвечивает пины с визитами год назад
- Маршрут до места (Directions) ✅ — уже реализовано, см. Phase 1D
- **Маленький значок погоды** — иконка текущей погоды (для центра карты/GPS-точки) где-то
  в углу экрана, без отдельного экрана/детализации — просто «что сейчас на улице»,
  не полноценный прогноз

Убрать: рейтинговые звёзды на карте, чужие отзывы — это Apple Maps, не мы

### 2. Поиск — встроен в карту

**Стать**: Поиск — воронка добавления пина, не самоцель.

  (уже реализовано: `SearchResultMarker` → `handleConfirmSearchResultMarker`)

### 3. My Places / Remembrance (Мои места)

**Стать**: Личный атлас с фильтрами.

- Три вида: список / сетка фото / мини-карта
- Фильтры: категория, тег, настроение, люди, период
- Статистика (мини-виджет): сколько мест, любимая категория, самый активный месяц

### 4. Place Detail (Детали места)

- Timeline воспоминаний по датам
- «Добавить воспоминание» — mood picker, фото, companions
- Теги — inline chip-редактирование
- Кнопка «Предложить встречу здесь» → CreateMeeting с этим местом

---

### 5. Create Memory

Step-by-step: фото → настроение → с кем → заметка → дата. Уже реализовано (Phase 1A).

---

### 6. CreateMeeting / Meeting Negotiation

- Название встречи + дата
- Предложить места (кандидаты из своих мест)
- Участники (Phase 1 — имена/контакты текстом, Phase 2 — реальные пользователи)
- Приглашение — шарится ссылкой через Share Sheet (**не** через native-чат — держим
  трение приглашённого минимальным, см. стратегию валидации выше)
- Статус: draft → proposed → confirmed → done

---

### 7. Profile

- Счётчики: мест, воспоминаний, встреч, уникальных городов
- Любимые теги/категории — облако
- (Phase 1C+) Карта вкусов, «Мои паттерны» — только после AI-ассистента

---

### 8. Ask (AI-ассистент) — строить только после подтверждённого роста

**Не строить вслепую до Phase 0-теста (см. стратегию валидации).** Как только сигнал
есть — план не меняется:

- Anthropic API (`claude-haiku-4-5`)
- Контекст = JSON с местами/тегами/mood/companions пользователя, без внешнего поиска
  (privacy-first)
- Примеры запросов: «куда пойти сегодня вечером», «где мы с Машей обычно встречаемся»,
  «предложи маршрут на выходные»
- Это первая реальная платная фича — premium/subscription gate с первого дня реализации

## ✅ Принципы, которым должен следовать Claude при реализации

1. **Поиск = утилита, не дифференциатор** — внешний поиск (Mapbox) существует только
   чтобы добавить новый пин или найти реальный бизнес; не строить вокруг него фичи
2. **Категория — маленький фиксированный enum, теги — свободный пользовательский ввод**
   — не смешивать эти две системы, не делать категории полностью пользовательскими
3. **Никаких чужих отзывов и агрегированных рейтингов** — это делает нас Apple Maps
4. **Mood/emotion first** — каждое место должно иметь эмоциональный/личный контекст
5. **Не строить фичи вслепую** — AI-ассистент, реклама, calendar-интеграция, live
   location — всё это только после подтверждённого share/invite rate на Phase 0-тесте
6. **Meeting-приглашение = ссылка, минимальное трение** — не требовать установку
   приложения для голосования там, где можно обойтись веб-fallback
7. **Design tokens везде** — `Colors.*`, `Typography.*`, `Spacing.*`, `Radii.*`
8. **Hooks не импортируют UI-компоненты** — вся логика в `useXxxScreen.ts`, экран — чистый рендер
9. **AI работает только на своих данных** — никакого внешнего поиска в Ask, только
   локальный контекст пользователя
10. **Монетизация — subscription, не ads** — конфликтует с личным позиционированием
    и не даёт значимого дохода на маленьком DAU
